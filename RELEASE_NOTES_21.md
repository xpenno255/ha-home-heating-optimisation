- Added explicitly approved bounded heating trials (`propose_trial`, `approve_trial`, `start_trial`, `stop_trial`, `reject_trial`, `evaluate_trial`, `get_trials`): one allowlisted tuning parameter per trial (room `trust_k`/`cap_up`/`cap_down`, boiler `design_flow`/`design_outdoor`/`return_ceiling`) with bounds, max step, baseline, predeclared success/stop criteria, expiry and rollback captured at proposal.
- Trials only run on a scope that is already active/auto with ownership ready and no activation blocker; they never change modes, enable switches, DHW protection or issue actuator commands, and DHW `dhw_delta` is excluded from the allowlist.
- Running trials are supervised every minute and rolled back with readback verification on expiry, comfort-floor or degree-hour breaches, manual override, mode change, stale/guarded sources, `stop_trial`, integration unload and the next startup; an unverified rollback raises a `trial_rollback_failed` Repairs issue.
- Evaluations record predeclared criteria beside measured metrics, label measured air separately from estimated operative comfort, keep inconclusive outcomes and are tagged as association evidence; a `Trials` sensor exposes counts only.
- Trial state persists in a validated, bounded store that becomes read-only on corruption without affecting heating control; transitions are journaled when the journal is available. See docs/bounded-trials.md.
